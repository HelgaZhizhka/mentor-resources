## Чеклист Code Review: Clean Code

Этот чеклист — не набор абсолютных запретов. Используйте его как ориентир: оценивайте влияние проблемы на читаемость, поддержку, требования задания и уровень студента.

### ✅ Именование

- [ ] Имена понятны без комментариев
- [ ] Нет однобуквенных переменных (кроме i, j в циклах)
- [ ] Boolean переменные начинаются с is/has/should
- [ ] Функции — глаголы, классы — существительные
- [ ] Нет сокращений (кроме общепринятых)

### ✅ Функции

- [ ] Функция делает одно действие
- [ ] Функция обычно не больше 20-30 строк; если больше — есть понятная причина
- [ ] Параметров <= 3 (или объект параметров)
- [ ] Нет побочных эффектов (или они явные)
- [ ] Early return используется там, где уменьшает вложенность
- [ ] Один тип возврата

### ✅ Код

- [ ] Нет дублирования (DRY)
- [ ] Нет мёртвого кода
- [ ] Вложенность <= 3 уровней
- [ ] Magic numbers вынесены в константы
- [ ] Код простой (KISS)
- [ ] Нет over-engineering (YAGNI)
- [ ] Скобки обязательны для всех блоков if/else/for
- [ ] Размер файла не превышает 400 строк
- [ ] Event delegation используется для списков и динамических элементов

### ✅ Принципы SOLID

- [ ] Single Responsibility соблюдается
- [ ] Open/Closed где применимо
- [ ] Dependency Inversion для гибкости

### ✅ Ошибки

- [ ] Ошибки обрабатываются
- [ ] Есть валидация входных данных (Fail Fast)
- [ ] Try-catch не пустые
- [ ] Optional chaining (`?.`) используется для безопасной работы с nullable-данными
- [ ] Nullish coalescing (`??`) используется там, где `0`, `''` и `false` должны сохраняться

### ✅ Комментарии

- [ ] Комментарии объясняют "почему", а не "что"
- [ ] Нет устаревших комментариев
- [ ] TODO/FIXME актуальны и с датами
- [ ] Нет закомментированного кода

### ✅ Асинхронный код

- [ ] Используется async/await вместо callbacks
- [ ] Все промисы обрабатываются (await или .catch)
- [ ] Независимые параллельные запросы выполняются через `Promise.all` / `Promise.allSettled`
- [ ] Cleanup для `setInterval` / `setTimeout` / subscriptions
- [ ] Запросы можно отменить через `AbortController`, если есть риск race condition или unmount

### ✅ Данные

- [ ] Используется immutability
- [ ] Для массивов выбран читаемый подход (`map`, `filter`, `reduce`, `find`, `some`, `for...of`)
- [ ] Объекты обновляются иммутабельно, например через spread operator
- [ ] Нет мутации параметров

### ✅ Тестируемость

- [ ] Функции чистые где возможно
- [ ] Dependency Injection используется там, где снижает связность или упрощает тестирование
- [ ] Логика отделена от side effects
- [ ] Нет глобального состояния

### ✅ TypeScript

- [ ] Нет явного и неявного `any`
- [ ] Данные извне (`fetch`, `JSON.parse`, `localStorage`) проходят через `unknown` + type guard/validation
- [ ] `as` и non-null assertion (`!`) не используются для маскировки ошибок типов
- [ ] Union states описаны явно, где это упрощает логику (`status: 'loading' | 'success' | 'error'`)
- [ ] Доступ по индексу/ключу учитывает возможный `undefined`

### ✅ React

- [ ] Effects имеют корректный cleanup и dependency array
- [ ] Нет derived state через `useEffect`, если значение можно вычислить во время render
- [ ] `useMemo`, `useCallback`, `React.memo` используются только при реальной причине
- [ ] Нет прямого управления UI через DOM API (`querySelector`, `classList`, `style`) внутри React-компонентов
- [ ] Списки имеют стабильные `key`, не index для изменяемых списков

### ✅ HTML/CSS/UI

- [ ] Семантическая разметка и связанные `label` для форм
- [ ] Изображения имеют корректный `alt`; декоративные — `alt=""`
- [ ] LCP-изображение не lazy-loaded, изображения ниже fold можно `loading="lazy"`
- [ ] Видимый focus state (`outline` / `:focus-visible`)
- [ ] Анимации учитывают `prefers-reduced-motion`
- [ ] Нет горизонтального overflow на 320px; flex/grid overflow обработан (`min-width: 0`, где нужно)

### ✅ Форматирование

- [ ] Код отформатирован (Prettier)
- [ ] ESLint правила соблюдены
- [ ] Импорты упорядочены
- [ ] Длина строки <= 100-120 символов

## Заключение

**Главные принципы чистого кода:**

1. **Читаемость** — код должен быть понятен с первого взгляда
2. **Простота** — простое решение всегда лучше сложного (KISS)
3. **Модульность** — каждая часть делает одно и делает хорошо (SRP)
4. **Предсказуемость** — код работает так, как ожидается
5. **Тестируемость** — код легко покрыть тестами
6. **Поддерживаемость** — изменения вносятся без страха что-то сломать

**Запомни:**

- ✅ Чистый код экономит время команды
- ✅ Рефакторинг — непрерывный процесс
- ✅ Следуй правилу бойскаута: оставляй код чище, чем нашёл

**Следующие шаги:**

- Применяй эти принципы в своём коде
- Делай code review с этим чеклистом
- Постоянно улучшай свои навыки
- Делись знаниями с командой
