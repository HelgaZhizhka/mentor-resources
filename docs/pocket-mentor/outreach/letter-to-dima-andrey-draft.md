## Что изменилось vs. предыдущей версии

1. **Главный технический пойнт сместился.** Было: *"я упакую промпт в skill"*. Стало: *"я НЕ дублирую ваши рубрики — engine читает их прямо из `rolling-scopes-school/tasks`"*. Это вообще другой уровень alignment'а со школой.

2. **Hook теперь двойной:** вопрос Олега + анонс "ТЗ будут меняться". Связка делает архитектурное решение (источник истины = школа) неизбежным выводом, а не моим капризом.

3. **Score authority зафиксирован явно** — ментор всегда последнее слово. Закрывает потенциальный возражение про "AI выставляет оценки".

4. **Убраны детали** — auth-каскад, 3 режима CLI, package layout, paid composer. Это всё для созвона, не для письма.

5. **Один вариант, ~350 слов.** Не два. Хватит для всех каналов.

## Почему такой порядок (анатомия)

| Абзац | Зачем |
|---|---|
| Приветствие + спасибо за лекцию | Контекст, не льстит |
| Олег + "ТЗ будут меняться" | **Двойной hook.** Один вопрос → проблема. Второй факт → проблема будет ухудшаться. Создаёт urgency |
| "У меня есть наработки" | Моя легитимность: я уже в их доках, я уже это год использую |
| **Архитектурное решение** | Главный технический punchline. Если вынести в начало — потеряется без контекста. Если вынести в конец — заглохнет. Середина = верно |
| Форма (скилл + CLI + draft review) | Конкретика, что именно делаем |
| Пилот | Снижает риск ответа "это слишком большой проект". Маленький, ограниченный, бесплатный |
| Ask + sign-off | Чёткое следующее действие = 30 минут созвон |

## Что осознанно НЕ написано

1. **Paid web composer.** По твоему запросу — не упоминаем нигде. Если на созвоне спросят "а в чём твоя выгода" — отвечаешь честно: *"Долгосрочно — paid композер для менторов из других школ, не для RS School. Здесь — open-source контрибьюшен."*

2. **Конкуренция с Tandem.** Tandem — про процесс обучения через дневник; Pocket Mentor — про ревью кода. Разные продукты. Не задевать.

3. **Детали реализации (TS/Node, monorepo, package layout, auth cascade).** Не для письма. Раскрутишь на созвоне если будут спрашивать.

4. **Финансовые/cost estimates.** Они уже знают, что они бедные. Подчёркивать = снисхождение.

5. **"Я ваш следующий мейнтейнер AI-стрима".** Слишком сильное заявление. Пусть сами это поймут по результатам пилота.

## Ответы на типовые возражения (для созвона)

### *"А зачем нам это, у нас уже есть GPT-5.5 для ревью"*

→ "GPT-5.5 даёт ревью **против общих best practices**. У вас async-race — 8 категорий с конкретными баллами, штраф -100% за React, штраф -100% за `any`. GPT этого не знает, потому что это не публичная информация. Engine знает — потому что читает вашу же markdown. Это разные продукты."

### *"А почему бы нам самим не сделать?"*

→ "Можете. Но у меня это уже год работает в проде на моих потоках. Я готова отдать школе бесплатно, сама буду мейнтейнить. Вам — нулевая стоимость и нулевые риски. Если я disappear — форкаете в любой момент, рубрики и так ваши."

### *"А что если школа поменяет формат markdown?"*

→ "Enrichment-файлы пинятся к конкретному commit SHA школьного master'а. Weekly CI-job на нашей стороне проверяет diff. Если ваш markdown поменялся — открывается PR, я ревьювлю, при необходимости обновляю enrichment. Никаких автоматических ломок в проде."

### *"А кто отвечает за балл — AI или ментор?"*

→ "Ментор. Engine всегда отдаёт `estimated_score` как suggestion. В draft review summary ментор видит цифру и может её изменить до submit. Никакого автоматического выставления оценок."

### *"А оно правда работает или это вайп-код?"*

→ "Промпт у меня в проде год. Скрипты тоже. Engine — это **обёртка** над этим, не with-scratch build. Качество промпта = качество того что у меня сейчас работает. Можешь сам прогнать ручками через `mentor-resources/templates/agents/reviewer.md` — это и есть ядро."
